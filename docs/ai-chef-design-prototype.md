# AI Chef Design Prototype

Status: isolated, interactive phase-1 design prototype. Not merged to main,
not published and not connected to production, Supabase or any AI provider.

## Run and Build

From this repository, with its dependencies installed and Node/npm configured:

```sh
npm run dev:chef
npm run build:chef
npm run preview:chef
```

The development URL defaults to `http://127.0.0.1:5200`; Vite selects another port
if occupied. Production preview defaults to `http://127.0.0.1:5201`.

This is a separate preview entry inside the existing repository, not a second
product or an application rewrite. Its standard React/Vite configuration is
`prototypes/chef/vite.config.ts`; it does not import the Lovable build wrapper,
contact Lovable, generate routes or change the existing application's entry.
The main package still contains the existing production wrapper dependency;
this milestone does not claim that the production migration is finished.

## Screens

- Home: food photography, ingredient/AI entry, recipe inspiration and an explicitly
  illustrative memory section. A started local session can be resumed here.
- Kitchen: searchable cookbook, saved-recipe and quick-recipe filters; ingredient
  workbench with removable/addable ingredients, time and oven constraints. Results
  are filtered from three fixed examples, not generated by an AI model.
- Recipe: ingredients with real portion arithmetic, checklist, method and contextual
  Chef entry. Optional nutrition layout shows unknown values, not invented macros.
- Cook: local step progression, named multi-timers, pause/resume/restart/removal,
  ingredients, contextual help and a small post-cooking feedback interaction.
- Wine: illustrative pairing and entry points to the existing public WineSnap
  cellar/scanner, opened only on explicit link selection. No real cellar is loaded.
- You: confirm/edit/forget example memories and a default-off optional Keto toggle.
  No ketone measurements, medical functions, family records or health collection.
- Chef: one context-aware presentation for general, recipe and active-cooking help,
  clearly labeled as fixed sample replies, not a real AI conversation.

All prototype choices are held in the current page's memory. Reload clears them.
No localStorage, IndexedDB, account session, cookies, database writes or analytics
are used. Leaving a cooking view does not reset its local state. Starting another
example session requires confirmation before resetting the current sample session
and timers. Opening the same recipe resumes the existing session instead.

Timers use absolute deadlines and paused remaining time, not accumulated interval
ticks. They are a local foreground demonstration, not a background alarm, physical
device notification or phase-2 persistent/offline cooking implementation. They do
not determine when food is safe or finished. Example recipes are not a validated
food-safety corpus. Recipe scaling changes ingredient quantities only.

## Design Boundaries

Light neutral paper, forest-green structure, editorial serif headings, clear
sans-serif controls and culinary imagery. No old burgundy/gold shell is changed.
The mobile navigation is Home/Kitchen/Cook/Wine/You; desktop uses the same set in
a restrained sidebar. Cook keeps large instructions and tablet ingredient/timer
space; narrow screens stack these areas. Optional Keto never replaces the default
experience or displays unsupported nutrient values.

Native dialog focus containment/Escape, keyboard-operable kitchen tabs, labeled
icon controls, reduced-motion styles and safe-area spacing are included. These
are not a complete screen-reader or real-device accessibility certification.

See [image sources and exact generation prompts](../src/features/chef-prototype/assets/CREDITS.md).
Generated WebP photographs are bundled locally alongside the reference pasta
photograph. No live image service or AI API is needed to view the prototype.

## Verification

The checked-in optional browser script uses a fresh headless Edge context and
accepts loopback URLs only:

```sh
node scripts/check-chef-prototype.mjs http://127.0.0.1:5200
```

It expects Playwright to be installed separately or supplied through
`PLAYWRIGHT_MODULE` as a module URL; no dependency install is performed in the
existing shared `node_modules` junction. Screenshots/results go to ignored
`dist/chef-prototype-qa`.

Checks cover four viewport sizes (360, 390, 1024 and 1440 pixels), eight main
screens, decoded images, horizontal overflow, portion changes, real timer
pause/resume, contextual sample chat, memory changes, Keto opt-in, search-empty
state, ingredient matching, dialog Escape, feedback and state clearing on reload.
All external requests are rejected/reported by that test; it must not contact
production or providers. The old WineSnap links are not followed during testing.
Focused unit tests also cover deadline/pausing, formatting, bounds, scaling and
honest sample responses.
